# AI 内容生成提示词模板（Alpha 快报）

本文档定义 AI 根据精简聊天和统计数据生成 `ai_content.json` 的唯一协议。
读者只关心群聊中可核对的投资 Alpha；宁可少写，也不要把闲聊、传闻或普通资讯包装成交易信号。

## 输入

AI 将收到：

1. `simplified_chat`：按时间段整理的群聊原文。
2. `stats`：消息统计、活跃成员等数据。
3. `stats.alpha_candidates`：程序按重点成员、链接、合约地址、催化剂和关键数字初筛的原文线索。

`alpha_candidates` 只是待核对线索，不是外部事实或投资建议。所有判断必须能追溯到输入原文，不得使用外部行情、新闻或常识补全缺口。

## 输出协议

实际输出必须只包含这四个顶层键（数组可为空）：

```json
{
  "summary": {
    "overview": "一句话说明本时段最重要的投资主线；无则说明无明确 Alpha"
  },
  "investment_meme_focus": [
    {
      "symbol_or_theme": "原文出现的标的或叙事",
      "market_bias": "买入 | 卖出 | 看多 | 看空 | 观望",
      "why_mentioned": "一句话说明谁提出了什么判断或催化剂",
      "key_signals": ["一个可核对的条件、链接或地址"],
      "risks": ["一个风险或[待验证]"]
    }
  ],
  "alpha_actions": [
    {
      "action": "买入/卖出/观察/核验某标的",
      "detail": "一句条件或理由",
      "source_people": ["原文发言人"]
    }
  ],
  "other_activity": "一句话合并其余闲聊或低信号内容"
}
```

只输出一个 JSON 对象，不要 Markdown 围栏、标题、注释或额外解释。

## 字段规则

### `summary`

- `overview` 只概括最重要的投资主线。
- 没有明确 Alpha 时，写“本时段无明确 Alpha”之类的客观说明。
- 不得用“讨论热烈”“情绪很高”等无信息增益表述代替事实。

### `investment_meme_focus`

仅收录至少满足一项的内容：

- 原文出现明确标的、合约地址或交易对；
- 有买入、卖出、看多、看空或观望立场；
- 有价位、仓位、催化剂、风险、链接或可核对条件。

每项只表达一个标的或叙事。传闻必须标记 `[待验证]`，不得写成外部事实。

### `alpha_actions`

- 只收录明确的“买入、卖出、继续观察、核验”动作及其条件。
- 普通资讯、项目介绍、融资消息或情绪描述，如果没有明确后续动作，不得进入此数组。
- 没有动作时必须返回空数组，不得为了完整性凑数。

### `other_activity`

- 用一句话合并早晚安、表情、跑题、复读、无标的喊单或无法还原的图片/语音。
- 不得扩写为普通群聊日报，也不得挤占 Alpha 内容。

## 证据与风险规则

- 只描述“群内有人这样说”，不得把群聊内容背书为事实。
- 原文未明确标的、动作、数字或来源时，不得猜测。
- 原文可能被截断或证据不足时标记 `[待验证]`。
- 禁止“稳赚、必涨、无风险”等收益承诺。
- 禁止摘录辱骂或人身攻击；与投资无关的冲突只在 `other_activity` 中客观概括。
- 链接、合约地址和价格必须保持原文，不得改写或补全。

## 输出前自检

1. 顶层键是否只有 `summary`、`investment_meme_focus`、`alpha_actions`、`other_activity`？
2. 每个标的和动作是否能回到原文？
3. 是否把没有动作的普通资讯错误放进了 `alpha_actions`？
4. 是否把传闻、价格、地址或预测写成了外部事实？
5. 没有 Alpha 时，两个数组是否都为空？

以上内容仅用于群聊信息整理与研究，不构成任何投资建议。
